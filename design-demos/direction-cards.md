## 配色已绑定宿主（2026-11-11 追加）

三版原本各有一套自造色（暖纸 / 冷灰 / 荧光绿）。按「配色适配当前应用」的要求，全部改成只吃宿主 token，实现在 `assets/host-theme.css`：

| 语义 | 宿主 token | 浅色实测 | 深色实测 |
| --- | --- | --- | --- |
| 页面底 | `--dsw-alias-bg-base` | `#ffffff` | `#151517` |
| 卡片面 | `--dsw-alias-bg-layer-1` | `#ffffff` | `#232324` |
| 正文 | `--dsw-alias-label-primary` | `#0f1115` | `#f9fafb` |
| 次要字 | `--dsw-alias-label-secondary` | `#61666b` | `#cfd3d6` |
| 分隔线 | `--dsw-alias-border-l2` | `#0000001a` | `#ffffff1f` |
| 选中 / 链接 | `--dsw-alias-state-business-primary` | `#4176e6` | `#7aaaff` |
| 主行动 | `--dsw-alias-button-primary-fill` | `#0f1115` | `#f9fafb` |
| 通过 | `--dsw-alias-state-success-primary` | `#22c55e` | `#22c55e` |
| 待配置 | `--dsw-alias-state-warn-primary` | `#f59e0b` | `#f59e0b` |

这些值是用 Playwright 从运行中的 0.2.2-rc.1 实例 `getComputedStyle` 读出来的，不是从设计稿猜的。

绑定之后，三个方向**不再靠颜色区分**，区分点回到结构与字体：

- **A**：横向信息密度最高，项目架 + 并排双 console，适合「一边看项目一边看结果」。
- **B**：唯一的纵向阅读流，源码占主版心，适合「先读稿再决定」。
- **C**：唯一的表格式项目列表 + 三个大数字，适合「先看能不能跑」。

代价也要说清楚：A/B/C 的自造色被拿走后，B 的「纸感」没有了，C 的「荧光绿个性」也没有了——它们现在都像同一个应用里的三张不同布局。这是「适配当前应用」的直接结果。

## A · Dailies（媒体架）

**一句话**：这是一个剪片子的地方，不是文件管理器。

- **为什么是它**：Hypit 的产物是视频，行业内的人看「项目—素材—校验—执行」时脑子里是 NLE 的媒体架和时间码。用这套视觉语言，状态点、旁注、命令输出都能各归其位，且不需要解释。
- **版式**：顶部时间码尺（纯装饰性的行业锚点，不承载信息）→ 左侧项目架（LED 状态点 + 源/Run/时间）→ 右侧 inspector：四个量（Outputs / Requests / Sources / Runs）→ check 与 plan 并排两张「示波器」→ 源码分页签 → 底部指令条。
- **字体**：Inter Tight（界面与标题）+ IBM Plex Mono（所有数据）。中文回落 PingFang SC。
- **色彩**：底 `#0a0b0d`，面板 `#101216`，线 `rgba(255,255,255,.075)`；品牌粉 `#e83f5f` 只出现在选中条与主按钮；通过 `#35c08e`、告警 `#e0a63c`。
- **实施要点**：全部换成宿主 token（`--dsw-alias-bg-l1/l2`、`--dsw-alias-label-*`、`--dsw-alias-border-l3`），粉色保留为插件唯一强调色；深色随宿主主题走，浅色主题下自动退化为「浅底 + 深字 + 同一套 mono 层级」。时间码尺可换成一条 1px 刻度线，避免在浅色主题里显得突兀。
- **风险**：和最近几个深色工作台（网感口播、抖音报告）属于同一家族；如果想让这个插件在侧栏里一眼区分开，选 B 或 C。

## B · 剧本台（纸 · 衬线 · 页边）

**一句话**：SVML 是按词写的稿子，这个面板首先是一个读稿的地方。

- **为什么是它**：Hypit 的核心主张是「锚定到词而不是秒」。把源码当正文、把 check/plan 当页边批注，正好把这个主张变成界面语法——读的是稿，边上写的是能不能拍。
- **版式**：报头（衬线刊头 + 一行环境数据）→ 左侧项目索引（红蜡点标当前项）→ 中间主稿（章节页签 + 源码正文）→ 右侧页边（三条批注：校订 / 排期 / 还差一步）→ 底部批注条（选类型、写一句、写成草稿）。
- **字体**：Newsreader（标题与页边）+ IBM Plex Mono（源码）+ PingFang SC（正文）。
- **色彩**：纸 `#f4f0e6`，墨 `#23201b`，尺线 `#d8d1c0`；朱印红 `#a8372a` 只用于当前项与批注竖线；通过色用墨绿 `#3c6b4f`。
- **实施要点**：纸色改为宿主 `--dsw-alias-bg-l1`，不做纹理（纹理只在展示稿里）；页边在本宿主里空间紧张，窄屏时改为源码下方的「批注」块；衬线只用在项目名与批注，界面控件仍用宿主无衬线，避免与宿主冲突。
- **风险**：纸+衬线是当下很热的外观家族，容易和别的项目撞；另外「页边」在 1240px 以下会挤，需要一条折叠规则。

## C · 仪表（浅冷 · 数字优先）

**一句话**：先给结论——28 个产出、6 个请求、3.2 秒——再给证据。

- **为什么是它**：这个插件真正的价值不是「看文件」，而是「立刻知道这条片子能不能跑、要跑什么」。把三个数放到最大，命令输出作为证据链，正好对应 check/plan 的实际含义。
- **版式**：三栏——环境栏（LED + 根目录卡）｜项目表（源/Run 列右对齐、选中行荧光绿左条）｜观测区（三个巨型数字 → check/plan 两张证据卡 → Sources + 源码 → 底部 Brief）。
- **字体**：Space Grotesk（数字与项目名）+ IBM Plex Mono（命令与路径）+ Inter / PingFang SC（说明文字）。
- **色彩**：冷底 `#eef1f0`，卡 `#ffffff`，墨 `#0d1211`；信号绿 `#0e7c5a`；高亮荧光 `#c9f24d` 只用于当前行与状态章。
- **实施要点**：荧光绿在宿主深色主题下刺眼，需准备一组暗色替代（建议 `#8fbf3f`），或只在浅色主题启用；三个大数字用 tabular-nums 防止跳动。
- **风险**：荧光色个性强，和 DSH 现有的克制风格有距离；如果这个面板要长期待在侧栏，可能显得吵。

## 我倾向

**A** 最贴题材、落地最稳；**C** 最有信息效率，但需要为深色主题做第二套强调色；**B** 最有辨识度，也最需要窄屏规则。

如果只选一个且不想再返工：A。如果要在这个插件上形成长期语言、后面还要加 build 与结果预览：C 的三栏能直接容纳后续模块。
